# 命令面板交互方案（海报墙单入口）

状态：方案，待确认后实施。

## 1. 目标

- 海报墙成为唯一主界面。旧界面（侧边栏、曲库列表、工具栏、选择栏）的所有功能都迁移过来，入口统一收进一个命令面板。
- 移除海报墙左上角的「返回」和「来源切换」两个按钮（含 macOS 26+ 的原生版本 `wallChrome`）。
- `Cmd+K`（Windows/Linux 为 `Ctrl+K`）呼出/关闭面板。macOS 上面板使用液态玻璃。
- 面板打开后 `Tab`（或 `Shift+Tab`）切换搜索模式：默认「音乐库」，切到「功能」可搜索全部本地功能。
- 可发现性不是目标：没有引导提示，也不在界面上放入口按钮。

不在本方案范围：播放逻辑、曲库数据结构、在线来源与 WebDAV 协议本身。

## 2. 交互规格

### 2.1 呼出与关闭

| 按键 | 行为 |
|---|---|
| `Cmd+K` | 打开面板；已打开时关闭 |
| `Esc` | 有输入时先清空输入；输入为空时关闭面板 |
| 点击面板外 | 关闭 |
| 执行命令后 | 默认关闭；少数「切换类」命令（如夜间模式）保持打开，便于连续操作 |

面板打开时截获键盘事件：`Space` 不再触发播放/暂停，但其余播放快捷键（如 `Cmd+→` 下一首）仍然有效。

### 2.2 两种模式

面板标题区显示当前模式，`Tab`（或 `Shift+Tab`）在两种模式之间循环切换，输入内容保留：

1. **音乐库**（默认）：搜索歌曲、歌手、专辑和歌单，范围沿用现在的全局搜索（本地、已加载的云端、在线来源）。
2. **功能**：搜索所有本地功能，包括页面跳转、来源切换、导入、设置项等（完整列表见第 3 节）。

每次打开面板都回到「音乐库」模式。

### 2.3 结果列表操作

| 按键 | 行为 |
|---|---|
| `↑` / `↓` | 移动选中项 |
| `Enter` | 执行默认动作：歌曲→播放；歌单或来源→切换海报墙内容；功能→执行 |
| `Enter` / `Tab` | `Enter` 进入选中功能的二级列表（歌单、语言等），`Tab` 切换模式（切换时离开二级列表）；`Esc` 或空输入时 `Backspace` 返回上一级。歌曲的动作子列表（编辑信息、移除、下载音质）放在第 2 阶段 |

`Tab` 和 `Shift+Tab` 在面板内都被接管，不再用于移动焦点，焦点始终锁定在输入框。最初 `Tab` 用于进入二级列表、`Shift+Tab` 切换模式；由于 `Enter` 已能进入二级列表，改为 `Tab` 直接切换模式，保留 `Shift+Tab` 兼容旧习惯。

### 2.4 结果展示

- 音乐库模式按「本地 / 云端 / 在线 / 歌单」分组。本地结果即时出现，在线结果异步追加，并显示加载状态。
- 功能模式按「页面 / 曲库 / 播放 / 外观 / 设置」分组。输入为空时显示最近使用过的功能。
- 每条功能右侧显示它已有的快捷键（如果有）。

## 4. 技术设计

### 4.1 命令注册表（纯前端）

新增 `src/commands/`，把「功能」抽象成可注册、可搜索的命令：

```ts
interface AppCommand {
  id: string;                    // 'library.import-files'
  titleKey: string;              // i18n 键
  keywords?: string[];           // 中英文别名、拼音首字母
  group: 'page' | 'library' | 'playback' | 'appearance' | 'settings';
  shortcut?: ShortcutAction;     // 用于显示已有快捷键
  isAvailable?(ctx: CommandContext): boolean;   // 如「刷新」仅云端可用
  children?(ctx: CommandContext): AppCommand[]; // 二级列表：歌单、语言
  run(ctx: CommandContext): void | Promise<void>;
}
```

- `run` 只通过已有的 controller 回调发出意图（播放器 controller、曲库 controller、视图切换），不直接改 slot 状态，符合 AGENTS.md 的归属约定。
- 现有快捷键里的 `gotoBrowse`、`gotoSettings`、`gotoMetadata`、`focusSearch` 改为调用同一批命令，避免两套实现。
- 搜索使用轻量的模糊匹配（子序列匹配加拼音首字母）。先评估现有依赖；如果需要新增，优先选择成熟的小体积库。

### 4.2 面板状态与键盘

- `useCommandPalette` hook 负责 `open / mode / query / selection / stack`（二级列表栈），`CommandPalette` 组件负责渲染。
- 音乐库模式直接复用 `useGlobalSearch`，结果和现在的搜索页共用同一个数据来源。
- 在 `shortcuts.ts` 中新增 `toggleCommandPalette` 动作，默认键为 `Cmd+K`，可在快捷键设置里修改。

### 4.3 macOS 液态玻璃

网页内容无法画在原生玻璃「上面」：原生视图是盖在 webview 之上的，现有的控制条、专注模式控件和海报墙悬浮控件因此都是「原生控件 + 前端持有状态」的模式。面板有两种做法：

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A. 原生面板（推荐） | `NSGlassEffectView` 里放 `NSTextField` 和结果列表；前端计算结果后推送状态，原生回传输入和选择事件 | 与现有三个原生玻璃组件同一架构，玻璃效果真实，有现成代码可以参考 | 需要写一个带列表的原生视图，工作量最大 |
| B. 透明子窗口 | 面板是一个无边框透明子窗口，原生模块在它底部插入玻璃视图，网页负责画内容 | 界面仍然用 React 写 | 子窗口需要跨窗口同步曲库和命令状态，焦点与窗口层级问题多 |

推荐 A：延续现有模式，并复用 `playerControlbar.mm` 的状态推送、事件回传和降低透明度处理。非 macOS 平台以及 macOS 26 以下使用前端面板（毛玻璃 CSS）。两种实现共用同一个 `useCommandPalette` 状态，原生面板只负责显示。

### 4.4 移除与清理

- 删除 `WallChrome`、原生 `wallChrome.mm` 和对应的 IPC、类型与测试，以及 `LibrarySourceMenu`（来源切换改走命令）。
- 海报墙设为默认视图。满足以下条件后再删除 `Sidebar`、`LibraryView`、`LibraryToolbar`、`LibrarySelectionBar` 等列表相关代码：对照表中所有功能都已迁移，并通过验收。
- 视图记忆（上次停留在列表还是海报墙）改为只记住当前来源。

## 5. 风险

1. **快捷键冲突（已验证）**：最初设想的 `Ctrl+Space` 在 macOS 上默认是「选择上一个输入法」，开启多个输入法时系统会先截获，应用收不到（2026-09-27 在 macOS 27 上确认）。因此默认键改为 `Cmd+K`（Windows/Linux 为 `Ctrl+K`），并可在快捷键设置里修改。
2. **原生列表工作量**：方案 A 需要自己写结果列表的虚拟化、选中高亮和分组标题。可以先只做固定行高的列表，最多显示约 50 条结果。
3. **海报墙缺少多选能力**：批量移除依赖多选，海报墙目前没有选中状态，需要单独补做。
4. **输入法组字**：原生 `NSTextField` 自带中文输入法支持；前端实现需要处理 `compositionstart/end`，避免组字过程中触发搜索或执行。

| 阶段 | 内容 | 验收 |
|---|---|---|
| 0. 验证 | 呼出快捷键冲突（已完成，改用 `Cmd+K`）；原生玻璃文本框的输入法与焦点 | 确定玻璃方案 |
| 1. 命令与前端面板（已完成） | 命令注册表、前端面板、两种模式和 `Shift+Tab`、对照表中全部命令 | 所有功能可以从面板完成；单元测试覆盖注册表和键盘状态 |

### 第 1 阶段结果与遗留

- 已完成：`Cmd+K` 呼出、两种模式与 `Shift+Tab`、命令注册表与二级列表、拼音搜索、设置分区直达、`Cmd+F` 改为打开音乐库搜索。
- 移入第 2 阶段：
  - 歌曲的动作子列表（编辑信息、移除、下载）：编辑框和删除确认目前归海报墙和列表各自持有，需要先提升到外层。
  - 「刷新云端」命令：云端加载和刷新（`useLibraryCloudSync`）目前在 `LibraryView` 内部，需要先提升到外层，否则删除列表视图后海报墙无法加载云端曲库。
  - 「进入多选」命令：依赖海报墙多选。
- 取消：`Cmd/Ctrl+Enter` 只定位不播放。现有 `handleSearchNavigate` 会同时切换来源并播放，没有单独定位的接口，收益不大。

- 已完成：移除海报墙左上角的返回与来源切换按钮（含 macOS 原生 `wallChrome` 与对应 IPC、类型和测试）；启动即进入海报墙，不再记忆列表或海报墙模式；从设置页打开歌单时回到海报墙。

### 第 2、4 阶段结果（瀑布流统一界面）

- 界面结构：海报墙（曲库或搜索结果）始终铺满窗口；设置改为浮在海报墙上的玻璃浮层（`Esc`、关闭按钮或点击外部返回）；控制条悬浮在底部；其余入口全部在 `Cmd+K`。侧边栏、顶部搜索框、曲库列表、搜索结果列表页已删除。
- 搜索结果：面板里的「查看全部结果」打开结果海报墙，顶部玻璃条显示查询词和「全部 / 本地 / 云端 / 在线」筛选；点击查询词回到面板继续修改，在线结果右键下载，`Esc` 回到曲库。
- 多选与批量移除：右键「选择多首歌曲」或功能「选择多首歌曲」进入；海报变为复选框，底部玻璃选择栏提供全选、移除、完成。
- 拖拽排序：把一张海报拖到另一张上，两首歌交换位置；拼贴尺寸与位置不变，只重新适配封面（`swapTracks`）。仅本地与在线历史可拖拽。
- 云端同步提升到外壳，海报墙下也会自动加载云端曲库；新增功能「刷新云端曲库」，加载与导入进度以顶部状态胶囊显示；本地海报墙支持拖入文件导入，空曲库显示导入按钮。
- 删除：「紧凑列表」设置（`la_list_density` 已列入退役键）、「曲库列表（旧版）」命令，以及仅供列表使用的组件与测试。
- 未迁移：歌手/专辑分类浏览（原列表左栏），`filterType` / `categorySelection` 状态仍保留在持久化结构中，后续可做成面板命令。
- 修复：构建时的 CSS 压缩会把同时写了 `backdrop-filter` 与 `-webkit-backdrop-filter` 的规则合并为只剩带前缀版本，Electron 不识别，导致命令面板和悬浮控制条的毛玻璃从未生效；样式表只写不带前缀的属性即可。

### 第 3 阶段结果（macOS 原生玻璃面板）

- macOS 26+ 且原生模块可用时，面板由 `nativePalette.mm` 绘制：`NSGlassEffectView` 内含模式切换（`NSSegmentedControl`）、`NSTextField` 输入框和 `NSTableView` 结果列表（分组标题、SF Symbol 或封面、副标题、快捷键、二级箭头）。其他平台、旧系统或原生失败时回退到前端面板。
- 状态仍归 React：`CommandPalette` 把当前模式、查询、结果和选中项推给原生（`useNativePalette`）；原生只回传意图（输入、上下移动、悬停、执行、Tab、Shift+Tab、Esc、空输入退格）。前端和原生共用同一套意图函数。
- 输入法：原生输入框在组字期间不回传查询，确认后才搜索。
- 快捷键：原生输入框持有键盘时，菜单栏未处理的 `Cmd` 组合键会转发给渲染进程，以 `keydown` 重新派发，全局快捷键（如 `Cmd+K` 关闭、`Cmd+→` 下一首）照常生效。
- 封面：主进程按 URL 异步加载（复用控制条的 `loadArtwork`，每个 URL 只取一次），再推给原生缓存；无法获取的封面显示 SF Symbol。
- 点击面板外：前端只保留半透明遮罩负责关闭；遮罩标记 `data-controlbar-passthrough`，原生控制条保持可见。
- 原生输入框取得键盘时页面会收到 `blur`；打开期间窗口焦点指示（第四个交通灯）忽略这次 `blur`，关闭后焦点交还网页。
