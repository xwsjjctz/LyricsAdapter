# Phase 4：建立 ViewModel 层

## 遵守的规则
- **Rule 1（迁移优先）**：ViewModel 只是把现有从 store/controller 解出的状态「重新打包」成 UI 友好的形状，不改任何业务行为、不改 store、不改 controller。
- **Rule 2（一次一个边界）**：本 Phase 只引入 ViewModel 边界。不动 store 内部、不动 controller、不动 usePlayback。
- **Rule 3/4**：每 commit 答 5 问；`audioRef` 封装、Online/Import VM 等留到后续,记 backlog。
- 路径：`src/viewmodels/`（roadmap §6.2）。
- 分支：沿用 `refactor/src-restructure-and-player-controller`。

## 本轮范围：先做 PlayerViewModel + LibraryViewModel（roadmap §6.3/§6.4）

### 明确**不**做（记 backlog）
- **OnlineViewModel**（onOnlineStreamPlay/onOnlineDownload/onOnlineUpload/onlineProgress/onOpenOnlinePlaylist）—— 这些目前散在 playerController + useOnlineMusicIntegration，roadmap §6.2 列为独立 VM。先保持原样透传。
- **ImportViewModel**（fileInputRef/onFileInputChange/onImportIntoSlot/onReloadUnavailable/importProgress/onDrop*）—— import 流程，独立域。
- **audioRef 完整封装** —— FocusMode 的 RAF 歌词循环（FocusMode.tsx:142-176）硬依赖原始 audio 元素,需 60fps。slice 1 保留 audioRef 作为 PlayerViewModel 的逃生舱（roadmap §6.5 明确允许）。
- onClearOrphanCache —— app 级缓存服务编排,非 VM 形态,留 AppWorkspace。

## Slice 1：PlayerViewModel（先做，最大去重收益）

### 设计
```ts
// src/viewmodels/usePlayerViewModel.ts
export interface PlayerViewModel {
  // 状态读取
  currentTrack: Track | null;
  isPlaying: boolean;
  currentTime: number;
  duration: number;          // = currentTrack?.duration ?? 0（目前在调用点 inline 派生）
  volume: number;
  playbackMode: PlaybackMode;
  audioRef: React.MutableRefObject<HTMLAudioElement | null>;  // 逃生舱（slice 1）
  // 意图回调
  togglePlay(): void;
  next(): void;
  previous(): void;
  seek(time: number): void;
  changeVolume(v: number): void;
  toggleMute(): void;
  togglePlaybackMode(): void;
}
```
**输入**：接收 `usePlayerStore` 的返回（currentTrack/isPlaying/currentTime/volume/playbackMode/togglePlay/skipForward/skipBackward/handleSeek/handleVolumeChange/handleToggleMute/handleTogglePlaybackMode/audioRef）。
**输出**：上述 14 字段。`duration` 在 VM 内派生。

### 替换的 5 处重复（同一份 player bundle 现在写 5 遍）
1. AppWorkspace → `<Controls>`（legacy）
2. AppWorkspace → `<FocusMode>`（legacy）
3. AppWorkspace → `<NewUxShell>`（player props）
4. NewUxShell 内部 → `<FloatingPlayerPanel>`
5. NewUxShell 内部 → `<FocusMode>`

替换后：`const player = usePlayerViewModel(...)` 在 AppWorkspace 解一次,以 `player={player}` 传入两个 shell；NewUxShell 内部再透给 FloatingPlayerPanel/FocusMode。组件 props 形状**保持不变**（VM 字段名与现有 prop 名一致,组件内部解构不改）——这是关键:VM 是「在 AppWorkspace 装配层替换掉手动逐字段透传」,组件本身的 props 接口这次不动。

### Commit P4-1
新建 `usePlayerViewModel.ts`，AppWorkspace 用它替换 NewUxShell + Controls + FocusMode 的 player props 透传。

## Slice 2：LibraryViewModel

### 设计
```ts
// src/viewmodels/useLibraryViewModel.ts
export interface LibraryViewModel {
  // 状态
  slots: Record<SlotId, LibrarySlot>;
  activeSlotId: SlotId;
  viewSlot: SlotId;
  cloudImportDisabled: boolean;
  cloudImportDisabledReason?: string;
  // 意图
  switchViewSlot(id: SlotId): void;
  selectTrack(index: number, slotId?: SlotId): void;  // 保留可选 slotId 覆盖
  removeTrack(id: string, deleteFile?: boolean): Promise<void>;
  removeTracks(ids: string[], deleteFile?: boolean): Promise<void>;
  reorder(from: number, to: number): Promise<void>;
  updateTrack(track: Track): void;
}
```
**输入**：`useLibraryStore`（slots/activeSlotId/viewSlot/cloudWritable）+ `playerController.handleTrackSelect` + `libraryController`（remove/removeTracks/reorder/updateTrack）+ i18n（cloudImportDisabledReason）。
**明确不暴露**：`updateSlot`、`setActiveTracks`（roadmap §6.4「UI 不需要知道 current slot implementation」）。

### 替换
AppWorkspace 用它替换 NewUxShell + LibraryView 的 library 透传。**Legacy-only props（filterType/categorySelection/scrollPosition/autoLocateToken/pendingSlotLocate 协议/loadCloudTracks/mergeCloudTracks）保持原样透传给 LibraryView**,不进 VM。

### Commit P4-2
新建 `useLibraryViewModel.ts`，AppWorkspace 用它替换 NewUxShell + LibraryView 的 library props。

## 风险
- VM 字段名必须与现有 prop 名**完全一致**,否则组件 props 接口要改,扩大爆炸半径。我会逐字段核对。
- `duration` 现在在调用点 inline 派生（`currentTrack?.duration || 0`）,VM 集中派生时保持同样的 `?? 0` 语义。
- LibraryViewModel 的 `selectTrack` 要保留 `playerController.handleTrackSelect` 的可选 `slotId` 覆盖语义（New UI 跨 slot 播放依赖它）。
